# Сервер значков NebulaGram

Помнит, кому какой значок выдан, и отвечает **про одного человека за раз**.
Списка целиком наружу нет — это единственная причина, по которой сервис вообще
нужен вместо опубликованного файла.

## Что умеет

| | | |
|---|---|---|
| `GET /v1/badge/{id}` | открыто | `{"badge":"supporter"}` — это и видят все |
| `POST /v1/badge` | нужен токен | `{"id":123,"badge":"dev"}` |
| `DELETE /v1/badge/{id}` | нужен токен | снять значок |
| `GET /healthz` | открыто | для мониторинга |

Пустой `badge` в `POST` равнозначен `DELETE`. Ответ приходит и когда значка
нет — иначе по коду ответа можно было бы перебором составить тот самый список,
которого мы не отдаём.

Виды значков: `supporter`, `dev`, `tester`, `star`, `heart`. Незнакомый вид
сервер не примет: клиент его всё равно не нарисует.

## Запуск

```bash
NEBULA_BADGES_TOKEN="$(openssl rand -hex 32)" \
NEBULA_BADGES_FILE=/var/lib/nebula-badges/badges.json \
NEBULA_BADGES_ADDR=127.0.0.1:8431 \
  ./badges
```

Токен короче 32 символов сервис не примет и не запустится.

## Рядом с Remnawave

Сервис о Remnawave ничего не знает и ничего в ней не трогает: свой порт, свой
файл, свой процесс. Обновление Remnawave его не задевает, и он не задевает её.
Конфликты начинаются там, где в чужой продукт дописывают своё, — здесь этого
нет по устройству.

Практически:

1. **Отдельный порт на localhost.** `127.0.0.1:8431` наружу не смотрит.
2. **Отдельный location в nginx**, рядом с тем, что уже обслуживает Remnawave:

   ```nginx
   location /v1/badge {
       proxy_pass http://127.0.0.1:8431;
       proxy_set_header Host $host;
       limit_req zone=badges burst=20 nodelay;
   }
   ```

   `limit_req` здесь не для нагрузки, а чтобы перебор идентификаторов был
   медленным. Зона объявляется в `http`:
   `limit_req_zone $binary_remote_addr zone=badges:10m rate=10r/s;`
3. **Отдельная директория для файла** и своя резервная копия. Файл маленький,
   переносится копированием.
4. **Свой systemd-юнит**, чтобы перезапуск Remnawave не трогал значки:

   ```ini
   [Unit]
   Description=NebulaGram badges
   After=network.target

   [Service]
   Environment=NEBULA_BADGES_TOKEN=…
   Environment=NEBULA_BADGES_FILE=/var/lib/nebula-badges/badges.json
   ExecStart=/usr/local/bin/badges
   Restart=always
   DynamicUser=yes
   StateDirectory=nebula-badges

   [Install]
   WantedBy=multi-user.target
   ```

Если значок должен следовать за оплаченной подпиской — **не добавляйте это в
Remnawave**. Пусть отдельный скрипт по расписанию читает её API и зовёт
`POST /v1/badge`. Remnawave остаётся ванильной и обновляется штатно.

## В приложении

Настройки → Внешний вид → Профиль:

- **Мой значок** — название и собственная векторная иллюстрация. Пять видов:
  кристалл, код, щит, звезда и сердце; системные эмодзи не используются.
- Служебный адрес и админ-токен больше не отображаются в настройках.
  Приложение использует встроенный адрес, сохранённые параметры совместимы.
- **Выдать значок** — остаётся на уже настроенных администраторских устройствах.
  Для новых устройств выдавайте значки через API сервиса. Панель спрашивает идентификатор
  (его же даёт «Скопировать ID» в профиле) и вид значка.

Панель не спрятана «по идентификатору владельца»: исходники открыты, и такая
проверка ничего не охраняет — её вырезают одной строкой. Охраняет токен,
который проверяет сервер: без него выдача не пройдёт, сколько панель ни
открывай.

## Что уже поднято

Сервис работает на NebulaGuard:

| | |
|---|---|
| Адрес для приложения | `https://hooks.nebulaguard.mooo.com` (вшит по умолчанию) |
| Служба | `nebula-badges`, слушает `127.0.0.1:8431`, автозапуск включён |
| Токен и настройки | `/etc/nebula-badges.env`, права 600 |
| База | `/var/lib/nebula-badges/badges.json` |
| Вход снаружи | `location /v1/badge` в блоке `hooks.nebulaguard.mooo.com` |
| Копия конфига до правки | `/opt/remnawave/nginx.conf.before-badges-*` |

Посмотреть токен: `cat /etc/nebula-badges.env`

Откат целиком:

```bash
systemctl disable --now nebula-badges
cp /opt/remnawave/nginx.conf.before-badges-* /opt/remnawave/nginx.conf
docker exec remnawave-nginx nginx -t && docker exec remnawave-nginx nginx -s reload
```

Оговорка: `/opt/remnawave/nginx.conf` принадлежит Remnawave. Её обновление,
которое перегенерирует этот файл, унесёт наш `location` — значки перестанут
работать, остальное нет. Вернуть — добавить блок заново.
