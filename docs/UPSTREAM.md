# Модель форка: как не ломаться при обновлениях Telegram

Это главный документ репозитория. Всё остальное подчинено одному правилу:

> **Апстрим никогда не редактируется «по месту». Наш форк — это оверлей из
> новых файлов плюс микроскопическая серия патчей.**

Классические форки (Nagram, Cherrygram и др.) правят исходники Telegram прямо в
дереве. Через год такой форк догоняет апстрим неделями. Мы делаем иначе.

## 1. Три вида изменений

| Вид | Где живёт | Конфликтует при обновлении ТГ? |
|---|---|---|
| **Оверлей** — наши новые файлы (весь NebulaLink, наши экраны, дизайн-слой) | `platform/<os>/overlay/**` | Никогда |
| **Патчи-хуки** — 1–3 строки в файлах апстрима | `patches/<os>/*.patch` | Иногда, и это единственное место |
| **Конфиг** — вызовы публичных API апстрима вместо правок | внутри оверлея | Никогда |

Цель — держать патчи в пределах **5 файлов на платформу**. Всё, что можно
сделать через публичный API Telegram (например, включить прокси через
`SharedConfig.ProxyInfo`), делается через него, а не патчем.

## 2. Раскладка репозитория

```
NebulaGram/
├── core/                    Go-ядро NebulaLink (общее для всех платформ)
├── vendor/                  git submodules — чистый апстрим, НЕ РЕДАКТИРУЕТСЯ
│   ├── telegram-android/    github.com/DrKLO/Telegram
│   ├── telegram-ios/        github.com/TelegramMessenger/Telegram-iOS
│   └── tdesktop/            github.com/telegramdesktop/tdesktop
├── platform/
│   ├── android/overlay/     наши .java/.kt/ресурсы, копируются поверх апстрима
│   ├── ios/overlay/         наши .swift + BUILD-файлы
│   └── desktop/overlay/     наши .cpp/.h + CMake
├── patches/<os>/            серия патчей, применяется git apply
└── scripts/                 sync-upstream, apply-overlay, build-*
```

Сборка любой платформы = `checkout submodule на нужный тег` → `скопировать
оверлей` → `применить патчи` → `собрать`. Рабочее дерево апстрима остаётся
чистым, поэтому обновление на новую версию Telegram — это смена тега сабмодуля.

## 3. Процедура обновления на новую версию Telegram

```bash
scripts/sync-upstream.sh android            # свежий коммит master
scripts/sync-upstream.sh android 62b56a07   # конкретный коммит
```

Про ссылки на версии: DrKLO перестал ставить теги после `release-9.7.6_3721`,
актуальные релизы (сейчас это **12.10.1, сборка 7038**) живут только в `master`.
Поэтому апстрим Android фиксируется коммитом, а не тегом; tdesktop и
Telegram-iOS теги ставят, там можно передавать тег. Клоны сабмодулей неглубокие
(`--depth 1`), скрипт дотягивает ровно ту ревизию, которую просят.

Скрипт делает:

1. `git fetch --depth 1` нужной ревизии и checkout на неё;
2. `git apply --check` каждого патча из `patches/android/`;
3. если все патчи легли — коммитит новый тег сабмодуля, готово;
4. если какой-то патч не лёг — печатает **только** этот патч и его файл;
   правится один хук, `git apply --3way`, патч перегенерируется.

Оверлей при этом не трогается вообще: наши файлы не пересекаются с апстримом.

## 4. Реестр хуков

Каждый патч обязан быть описан в `patches/<os>/HOOKS.md`: файл апстрима,
якорь (сигнатура метода), назначение и количество строк. Патч без записи в
реестре не принимается — это защита от «а откуда тут ещё одна правка».

### Android — целевой список хуков

| Файл апстрима | Что делаем | Строк |
|---|---|---|
| `ApplicationLoader.java` | `NebulaLink.init(context)` в `onCreate` | 1 |
| `ProfileActivity.java` (раздел настроек) | одна строка-переход в наш экран | 3 |
| `LaunchActivity.java` | обработка `nebulagram://` deep-link для импорта подписки | 3 |

Всё остальное — оверлей. Прокси включается через существующий механизм
`SharedConfig.ProxyInfo` (Telegram умеет SOCKS5 сам), поэтому **в сетевой стек
мы не лезем вообще** — это самая частая причина поломок в других форках.

### iOS — целевой список хуков

| Файл апстрима | Что делаем | Строк |
|---|---|---|
| `Telegram/BUILD` | добавить зависимость на модуль `NebulaLinkUI` | 2 |
| `AppDelegate.swift` | инициализация ядра | 1 |
| `SettingsController.swift` | один пункт меню | 4 |

### Desktop — целевой список хуков

| Файл апстрима | Что делаем | Строк |
|---|---|---|
| `Telegram/CMakeLists.txt` | `add_subdirectory(nebula)` | 2 |
| `settings/settings_main.cpp` | один пункт меню | 4 |
| `core/application.cpp` | инициализация ядра | 1 |

## 5. Правила, которые держат патчи маленькими

1. **Ничего не переименовывать и не переформатировать** в файлах апстрима —
   один лишний пробел превращает патч в конфликт.
2. **Вставлять, а не изменять.** Добавление строки конфликтует реже, чем
   правка существующей.
3. **Не трогать «горячие» файлы** (`ChatActivity.java`, `ChatMessageCell.java`,
   `history_inner_widget.cpp`) — они меняются в каждом релизе. Если очень
   нужно — искать точку расширения выше по стеку.
4. **Никаких правок в `.pb`, генерируемых файлах и зависимостях.**
5. Любая логика — в оверлее; в патче только вызов.

## 6. Ночная проверка совместимости

`.github/workflows/upstream-watch.yml` раз в сутки берёт последний тег каждого
апстрима и прогоняет `git apply --check`. Если патч перестал применяться —
автоматически создаётся issue с именем патча и файлом. Мы узнаём о поломке
в день выхода версии Telegram, а не когда сели обновляться.

## 7. Что делать, если хук всё-таки развалился

1. Открыть файл апстрима на новом теге, найти якорь.
2. Внести те же 1–3 строки вручную.
3. `scripts/regen-patch.sh <os> <patch-name>` — патч перегенерируется из diff.
4. Коммит с указанием версии Telegram, на которой чинили.

Средняя стоимость обновления при таком подходе — десятки минут, а не недели.
